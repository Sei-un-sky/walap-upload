# Usage Guide

This guide explains how to use Walap Upload and what every user-facing configuration field means.

Walap Upload has two files under the MCDReforged data folder:

- `config/walap_upload/config.json`: main configuration file. Edit this file.
- `config/walap_upload/metadata.json`: backup record index generated by the plugin. Do not edit it unless you are repairing records manually.

After editing `config.json`, run `!!wp reload` in the MCDR console or in game, or restart MCDReforged.

## Commands

```text
!!wp           show help
!!wp now       create and upload a backup immediately
!!wp list      list recent backup records
!!wp status    show whether a backup task and scheduler are running
!!wp clean     apply the retention policy now
!!wp reload    reload config/walap_upload/config.json
!!wp cn        switch command output to Chinese
!!wp en        switch command output to English
```

Only one backup task can run at a time. If a backup is already running, `!!wp now` will report that the task is already running.

## Default Config

```json
{
  "server_name": "survival",
  "language": "en",
  "world_root": "./server",
  "world_dirs": ["world*"],
  "backup": {
    "enabled": true,
    "interval_hours": 6,
    "format": "zip",
    "temp_dir": "./backup_tmp",
    "local_dir": "./backups",
    "keep_local_after_upload": true,
    "calculate_sha256": true,
    "save_commands": true
  },
  "upload": {
    "enabled": true,
    "mode": "all",
    "retry_count": 3,
    "retry_interval_seconds": 30,
    "targets": [
      {
        "name": "local_test",
        "type": "local",
        "enabled": true,
        "directory": "./remote_backups",
        "remote_prefix": "survival/"
      }
    ]
  },
  "retention": {
    "enabled": true,
    "keep_last": 10,
    "keep_days": 30,
    "delete_local": true,
    "delete_remote": false
  }
}
```

## Top-Level Fields

`server_name`

Name written into backup file names and metadata. The generated file name uses this form:

```text
<server_name>_full_<date>_<time>_<trigger>.zip
```

Example: `survival_full_2026-09-03_03-38-32_scheduled.zip`.

`language`

Command output language. Use `en` for English or `cn` for Chinese. The values `zh` and `zh_cn` are also normalized to Chinese internally. You can change this with `!!wp en` or `!!wp cn`; the command saves the new value back to `config.json`.

`world_root`

Base directory used to resolve relative entries in `world_dirs`. Relative paths are resolved from the MCDR working directory. Absolute paths are accepted.

Common values:

```json
"world_root": "./server"
```

Use this when the Minecraft server files are under an MCDR `server` directory.

```json
"world_root": "."
```

Use this when MCDReforged runs directly inside the Minecraft server directory.

`world_dirs`

List of world directories to archive. Entries can be exact directory names or glob patterns. Relative entries are matched under `world_root`; absolute entries are used as written.

Examples:

```json
"world_dirs": ["world"]
```

Backs up only `world`.

```json
"world_dirs": ["world*"]
```

Backs up directories such as `world`, `world_nether`, `world_the_end`, and `world_survival`.

```json
"world_dirs": ["world", "world_nether", "world_the_end"]
```

Backs up a vanilla-style world set explicitly.

If no configured world directory exists, the backup fails with `No world directories matched config world_dirs`.

## backup

`backup.enabled`

Controls scheduled automatic backups. `true` enables the scheduler. `false` disables scheduled backups. Manual `!!wp now` can still submit a backup because the manual command calls the backup service directly.

`backup.interval_hours`

Interval between scheduled backups, in hours. Decimal values are accepted because the scheduler converts the value to seconds using `float`.

Examples:

```json
"interval_hours": 6
```

Run every 6 hours.

```json
"interval_hours": 0.5
```

Run every 30 minutes. The minimum actual interval is 60 seconds.

`backup.format`

Archive format setting. In `v0.1.0`, the implementation creates zip archives, so keep this as `zip`.

`backup.temp_dir`

Temporary working directory reserved for backup operations. It is resolved like other relative paths from the MCDR working directory. In `v0.1.0`, the zip creation path mainly writes to `local_dir`, but keeping a dedicated temp path in the config preserves compatibility with future archive implementations.

`backup.local_dir`

Directory where local backup zip files are created. Relative paths are resolved from the MCDR working directory. The plugin creates the directory when needed.

`backup.keep_local_after_upload`

Whether local backup files should be kept after upload. This field is present in the config for user intent and future behavior. In `v0.1.0`, local deletion is controlled by the retention section after a backup finishes, especially `retention.delete_local`.

`backup.calculate_sha256`

When `true`, the plugin calculates the SHA-256 hash of the archive and stores it in `metadata.json`. This helps verify backup integrity. For very large backups, hashing adds extra disk read time after the archive is created.

`backup.save_commands`

When `true`, the plugin runs Minecraft save commands around archive creation:

```text
save-off
save-all flush
create zip archive
save-on
```

Upload starts after `save-on`, so world saving is only paused while the archive is being created. Set this to `false` only if your server environment does not support these commands or you deliberately want to manage saving yourself.

## upload

`upload.enabled`

Master switch for uploading. `true` uploads the archive to enabled targets. `false` keeps only the local archive and records an empty upload result.

`upload.mode`

Upload mode setting. The default is `all`. In `v0.1.0`, the uploader sends the backup to every enabled target regardless of this value, so leave it as `all`.

`upload.retry_count`

Maximum number of upload attempts per target. Values lower than 1 are treated as 1 attempt.

`upload.retry_interval_seconds`

Seconds to wait between failed upload attempts for the same target.

`upload.targets`

List of upload target objects. Each enabled target receives the backup independently. A backup status becomes `partial_failed` if at least one target reports failure.

## Common Target Fields

These fields are shared by all target types.

`name`

Unique display name for the target. This is used as the key in `metadata.json` upload results. Use stable names; changing a target name can prevent old remote backups from being deleted by retention because old metadata points to the previous name.

`type`

Backend type. Implemented values in `v0.1.0` are:

- `local`
- `webdav`
- `ftp`
- `ftps`
- `sftp`

Reserved but not implemented values include `s3`, `baidu`, `baidu_netdisk`, `unicom`, and `china_unicom_netdisk`. These placeholders will fail if used for real upload.

`enabled`

Whether this target is active. Disabled targets are skipped for upload and remote deletion.

`remote_prefix`

Path prefix placed before the backup file name on the remote side. Leading and trailing slashes are stripped internally.

Example:

```json
"remote_prefix": "survival/"
```

This produces remote paths like:

```text
survival/survival_full_2026-09-03_03-38-32_scheduled.zip
```

Use different prefixes to separate servers, seasons, or environments.

## local Target

Copies the backup to another local directory. This is useful for testing or for copying to a mounted disk.

```json
{
  "name": "local_test",
  "type": "local",
  "enabled": true,
  "directory": "./remote_backups",
  "remote_prefix": "survival/"
}
```

`directory`

Base local directory for copied backup files. The final path is:

```text
<directory>/<remote_prefix>/<file_name>
```

## WebDAV Target

Use this for Alist, NAS, Nextcloud, and WebDAV-compatible netdisk setups.

```json
{
  "name": "alist_webdav",
  "type": "webdav",
  "enabled": true,
  "url": "https://example.com/dav/minecraft-backups",
  "username": "user",
  "password": "pass",
  "timeout": 120,
  "remote_prefix": "survival/"
}
```

`url`

Base WebDAV URL. The plugin appends `remote_prefix` and the backup file name to this URL path.

`username`

WebDAV username. Leave empty only if your WebDAV endpoint allows anonymous writes.

`password`

WebDAV password, app password, or token depending on your provider.

`timeout`

HTTP connection timeout in seconds. Default is `120`.

Before upload, the plugin creates missing remote directories with WebDAV `MKCOL`.

## FTP / FTPS Target

Use `ftp` for plain FTP and `ftps` for FTP over TLS.

```json
{
  "name": "ftp_backup",
  "type": "ftp",
  "enabled": true,
  "host": "ftp.example.com",
  "port": 21,
  "username": "user",
  "password": "pass",
  "timeout": 60,
  "remote_prefix": "survival/"
}
```

`host`

FTP server host name or IP address.

`port`

FTP server port. Defaults to `21` for `ftp` and `990` for `ftps` if omitted.

`username`

FTP login username.

`password`

FTP login password.

`timeout`

Connection timeout in seconds. Default is `60`.

The plugin creates missing remote directories before uploading.

## SFTP Target

SFTP requires the Python package `paramiko` in the same Python environment used by MCDReforged.

```json
{
  "name": "backup_server",
  "type": "sftp",
  "enabled": true,
  "host": "backup.example.com",
  "port": 22,
  "username": "root",
  "password": "change-me",
  "key_filename": null,
  "base_dir": "/opt/walap-backups",
  "timeout": 60,
  "banner_timeout": 60,
  "auth_timeout": 60,
  "remote_prefix": "survival/"
}
```

`host`

SFTP server host name or IP address.

`port`

SSH port. Default is `22`.

`username`

SSH username.

`password`

SSH password. If `key_filename` is used and no password is needed, this can be empty.

`key_filename`

Path to an SSH private key file. This field is optional. Use an absolute path if possible.

`base_dir`

Base directory on the SFTP server. The final remote path is:

```text
<base_dir>/<remote_prefix>/<file_name>
```

If `base_dir` is empty, the plugin uploads relative to the SFTP login directory.

`timeout`

TCP connection timeout in seconds. Default is `60`.

`banner_timeout`

SSH banner timeout in seconds. Default is `60`.

`auth_timeout`

SSH authentication timeout in seconds. Default is `60`.

The plugin creates missing remote directories before uploading.

## retention

Retention runs automatically after each backup and can also be run manually with `!!wp clean`.

`retention.enabled`

Master switch for cleanup. `true` enables cleanup. `false` keeps all metadata records and files untouched by retention.

`retention.keep_last`

Always keep at least this many newest backup records. Example: `10` keeps the latest 10 backups even if they are older than `keep_days`.

`retention.keep_days`

Keep backups created within this many days. A backup is selected for cleanup only when it is outside the newest `keep_last` records and older than `keep_days`.

`retention.delete_local`

When `true`, cleanup deletes expired local backup zip files recorded in `metadata.json`.

`retention.delete_remote`

When `true`, cleanup also deletes expired remote backups that were uploaded successfully. Remote deletion uses target names stored in metadata, so keep target `name` values stable.

Conservative default:

```json
"delete_remote": false
```

This prevents accidental remote deletion until you intentionally enable it.

## metadata.json

`metadata.json` is generated by the plugin and stores backup records under `backups`. Each record may include:

- `id`: backup id based on creation time.
- `server_name`: server name from config.
- `created_at`: backup creation time.
- `trigger`: `manual` or `scheduled`.
- `file_name`: archive file name.
- `local_path`: local archive path.
- `status`: `running`, `archived`, `uploaded`, `partial_failed`, or `failed`.
- `world_dirs`: world directories included in the archive.
- `size`: archive size in bytes.
- `sha256`: archive SHA-256 if enabled.
- `upload_results`: per-target upload status and remote path.
- `retention_deleted`, `local_deleted`, `remote_deleted_count`: cleanup result fields.

The `!!wp list`, `!!wp status`, and retention cleanup behavior depend on this file.

## Common Recipes

Automatic backup every 3 hours:

```json
"backup": {
  "enabled": true,
  "interval_hours": 3
}
```

Keep local files only and disable upload:

```json
"upload": {
  "enabled": false
}
```

Keep the newest 20 backups and anything from the last 14 days:

```json
"retention": {
  "enabled": true,
  "keep_last": 20,
  "keep_days": 14,
  "delete_local": true,
  "delete_remote": false
}
```

Upload to both WebDAV and SFTP:

```json
"upload": {
  "enabled": true,
  "mode": "all",
  "retry_count": 3,
  "retry_interval_seconds": 30,
  "targets": [
    {
      "name": "alist_webdav",
      "type": "webdav",
      "enabled": true,
      "url": "https://example.com/dav/minecraft-backups",
      "username": "user",
      "password": "pass",
      "remote_prefix": "survival/"
    },
    {
      "name": "backup_server",
      "type": "sftp",
      "enabled": true,
      "host": "backup.example.com",
      "port": 22,
      "username": "root",
      "password": "change-me",
      "base_dir": "/opt/walap-backups",
      "remote_prefix": "survival/"
    }
  ]
}
```

## Operational Notes

- Store `config/walap_upload/config.json` securely because it may contain storage credentials.
- Test a new target with `!!wp now` and then inspect `metadata.json` for upload results.
- Use `!!wp status` to check whether the scheduler is active.
- Use `!!wp clean` after changing retention settings if you want cleanup to run immediately.
- Restore is manual: download a backup, stop the Minecraft server, replace the world directories, and start the server again.
